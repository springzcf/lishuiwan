# 云服务器一键部署

项目使用 Docker Compose 部署。首次在服务器完成域名、HTTPS、`.env` 和微信商户私钥配置后，以后每次更新只需一条命令：

```bash
git pull --ff-only && sh scripts/deploy.sh
```

部署脚本会依次执行生产配置检查、部署前数据库备份、镜像构建、容器更新、Flyway 数据库迁移、健康检查和页面探测。MySQL、Redis、上传文件使用 Docker 卷持久化，更新容器不会删除业务数据。

## 1. 服务器准备

建议使用已备案域名的 Linux 云服务器，至少 2 核 CPU、4 GB 内存和 40 GB 磁盘，并安装 Docker Engine、Docker Compose v2、Git。安全组只开放 SSH、HTTP 和 HTTPS，不要开放 3306、6379 或 8080。

服务号网页授权和微信支付必须使用 HTTPS。推荐由云负载均衡、CDN、宝塔/1Panel 或宿主机 Nginx 负责证书和 HTTPS，再转发到本项目 HTTP 端口。

如果宿主机反向代理占用 80 端口，在 `.env` 中设置：

```dotenv
HTTP_BIND=127.0.0.1
HTTP_PORT=8088
```

反向代理目标填写 `http://127.0.0.1:8088`，并传递 `Host`、`X-Real-IP`、`X-Forwarded-For`、`X-Forwarded-Proto` 请求头。可直接参考 [`deploy/host-nginx.conf.example`](../deploy/host-nginx.conf.example)，替换域名和证书路径后启用。公网始终只暴露 HTTPS 域名。

## 2. 首次部署

```bash
git clone 你的仓库地址 lishuiwan
cd lishuiwan
cp .env.example .env
mkdir -p secrets
chmod 700 secrets
```

编辑 `.env`，至少替换所有 `change-me`、`example.com`、示例 AppID 和商户配置。建议这样生成独立随机密码：

```bash
openssl rand -base64 36
```

将微信支付商户私钥放到：

```text
secrets/apiclient_key.pem
```

然后限制权限并部署：

```bash
chmod 600 .env secrets/apiclient_key.pem
sh scripts/deploy.sh
```

部署完成后访问：

- 服务号“活动”：`https://你的域名/h5/activity`
- 服务号“我的”：`https://你的域名/h5/mine`
- 管理后台：`https://你的域名/admin/`
- 微信支付回调：`https://你的域名/api/public/wx/pay/notify`

## 3. 日常更新

在服务器项目目录执行：

```bash
git pull --ff-only && sh scripts/deploy.sh
```

如果代码通过压缩包或 CI 上传，不需要拉取 Git，直接执行：

```bash
sh scripts/deploy.sh
```

也可以从自己的电脑直接触发服务器发布：

```bash
ssh 部署用户@服务器IP 'cd /opt/lishuiwan && git pull --ff-only && sh scripts/deploy.sh'
```

建议为部署用户配置 SSH 密钥登录，并赋予该用户访问 Docker 的权限；不要把服务器密码、`.env` 或微信商户私钥写进 Git 仓库。

数据库备份默认写入 `./backups`，保留 7 天。可指定其他持久磁盘：

```bash
BACKUP_DIR=/data/lishuiwan-backups sh scripts/deploy.sh
```

## 4. 常用排查命令

```bash
docker compose ps
docker compose logs --tail=200 api
docker compose logs --tail=200 web
docker compose restart api web
```

### 阿里云提示基础镜像 `not found`

如果 Maven、Java、Node、Nginx 等多个 Docker Hub 官方镜像同时在约 30 秒后提示 `failed to resolve source metadata` 或 `not found`，通常是 Docker Hub 网络或镜像加速器异常，并不表示这些官方标签真的不存在。

先登录阿里云容器镜像服务 ACR 控制台，在“镜像工具 → 镜像加速器”获取当前账号专属地址，然后将它加入服务器 `/etc/docker/daemon.json` 的 `registry-mirrors`，重启 Docker 后验证：

```bash
sudo systemctl daemon-reload
sudo systemctl restart docker
docker info | sed -n '/Registry Mirrors/,+5p'
docker pull public.ecr.aws/docker/library/maven:3.9.16-amazoncorretto-17-alpine
```

修改 `daemon.json` 前应先备份并保留其中已有配置。阿里云官方说明个人镜像加速器可能无法同步指定版本；正式生产更稳妥的方案是通过 ACR 制品订阅或自有仓库保存项目依赖的基础镜像，然后在 `.env` 指定完整地址：

```dotenv
MAVEN_BASE_IMAGE=registry.cn-hangzhou.aliyuncs.com/你的命名空间/maven:3.9.16-amazoncorretto-17-alpine
JAVA_RUNTIME_IMAGE=registry.cn-hangzhou.aliyuncs.com/你的命名空间/amazoncorretto:17-alpine
NODE_BASE_IMAGE=registry.cn-hangzhou.aliyuncs.com/你的命名空间/node:24-alpine
NGINX_BASE_IMAGE=registry.cn-hangzhou.aliyuncs.com/你的命名空间/nginx:1.28-alpine
MYSQL_BASE_IMAGE=registry.cn-hangzhou.aliyuncs.com/你的命名空间/mysql:8.4
REDIS_BASE_IMAGE=registry.cn-hangzhou.aliyuncs.com/你的命名空间/redis:7.4-alpine
```

私有 ACR 仓库还需要先执行 `docker login registry.cn-hangzhou.aliyuncs.com`。配置完成后重新运行 `sh scripts/deploy.sh`，首次失败没有创建数据库，不需要清理数据卷。

不要执行 `docker compose down -v`，其中 `-v` 会删除 MySQL、Redis 和上传文件卷。生产环境还应配置云盘快照或异地加密备份，并至少演练一次恢复。
