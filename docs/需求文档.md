# 丽水湾洗浴中心 · 会员管理系统 需求文档

> 版本: v1.4
> 日期: 2026-08-17
> 平台: 微信小程序(用户端 + 管理端,同一个小程序角色切换)+ Vue3 网页管理端 + Spring Boot 后端

> 文档状态: 已确认范围,可进入详细设计与开发。文中“必须/应”均为 v1 验收项,“可选/预留”不纳入 v1 验收。

---

## 一、项目概述

### 1.1 项目背景
丽水湾洗浴中心是一家提供大池、包间等多种洗浴服务的线下门店(单门店)。目前会员购卡、消费核销主要依赖人工,缺少面向顾客的自助入口和统一的卡资产/核销数据沉淀。

本项目由三端组成:
- **微信小程序(用户端)**:顾客使用,自助注册、购卡(微信支付)、出示会员码消费、查看权益卡与使用情况、接收核销通知。
- **微信小程序(管理端)**:门店核销员/管理员使用,扫码核销、现金发卡、查看数据报表(移动端现场操作)。
- **Vue3 网页管理端**:管理员在电脑端完成卡商品/活动配置、会员管理、订单管理、核销员授权、数据报表等重运营操作。

### 1.2 项目目标
1. 顾客侧:手机号一键登录 → 浏览活动 → 自助购卡(微信支付)→ 出示会员码消费 → 查看权益使用情况、接收核销通知。
2. 门店侧:核销员扫码核销(输入核销人 → 扫码 → 核销)、现金发卡(扫顾客会员码 → 现金发卡)、配置卡商品/活动、查看数据报表。
3. 单门店运营,仅售卡(无储值/充值),卡不支持转赠,不做预约,不做多门店,无退款流程。

### 1.3 本期范围边界(已确认)
| 项 | 决定 |
|---|---|
| 储值/充值 | ❌ 不做,仅售卡 |
| 卡转赠 | ❌ 不支持 |
| 会员等级 | 预留字段,v1 不做功能/UI |
| 积分 | 预留字段,v1 不做功能/UI |
| 预约 | ❌ 不做,仅到店核销 |
| 多门店 | ❌ 单门店 |
| 退款 | ❌ 不做 |
| 购卡方式 | ✅ 双通道:顾客微信支付自助购卡 + 管理端现金发卡 |
| 微信支付 | v1 模拟支付走通流程,预留微信支付接口,后期接入 |
| 卡商品/活动配置 | ✅ Vue3 网页管理端配置(重运营);小程序管理端仅现场核销/发卡/报表查看 |
| 管理端形态 | ✅ 小程序管理端(现场移动操作)+ Vue3 网页管理端(电脑端重运营) |
| 现金发卡顾客身份 | ✅ 顾客须已有会员账号(已用手机号登录过小程序) |
| 现金发卡操作方式 | ✅ 扫顾客会员码识别会员 → 选卡 → 填实收金额 → 发卡 |

### 1.4 名词约定
| 名词 | 说明 |
|---|---|
| 卡商品(权益卡模板) | 门店售卖的预付费/次卡商品,如"大池10次卡""包间月卡" |
| 权益卡 | 顾客购买后生成的实例,绑定会员,含独立有效期与剩余权益 |
| 权益 | 卡内含的可用内容,如"大池入场 N 次""包间使用 N 小时" |
| 有效期 | 卡自购买起可使用的截止时间 |
| 核销 | 顾客到店使用权益时,门店扫码扣减次数或时长 |
| 会员码 | 顾客出示的动态二维码,门店扫码识别会员与可用卡 |
| 核销人 | 扫码核销时由管理端输入的操作员姓名/工号 |

### 1.5 核心业务规则
1. 所有金额单位为人民币元,接口与数据库使用 `decimal(10,2)`,禁止使用浮点数计算。
2. 所有业务时间按 `Asia/Shanghai` 展示;数据库统一保存时间,前后端不得以设备本地时间判断订单或卡是否过期。
3. 商品下单后以订单快照为准。后续修改商品名称、价格、权益或有效期,不得影响历史订单和已生成权益卡。
4. 一个订单 v1 仅包含一种卡商品、数量固定为 1;订单明细按可扩展结构设计,后续可支持购物车。
5. 卡有效期从支付/现金发卡成功时开始计算,截止时刻为 `valid_from + valid_days`;到达截止时刻即不可核销。
6. 次数权益仅允许正整数;时长权益最小核销单位由商品配置(默认 0.5 小时);不限次权益只记录使用次数,不扣减余额。
7. 核销、模拟支付和现金发卡均必须防重复提交;同一请求重复到达不得重复扣减权益、重复发卡或重复记账。
8. 已产生订单的卡商品不得物理删除,仅允许下架或逻辑删除;历史订单、卡和报表仍可查询。
9. 成交价规则固定为:当前时间处于商品活动价有效期且活动价已配置时取活动价,否则取售价;价格与权益均在创建订单时固化为快照。

## 二、角色与权限

角色判定分两端:
- **小程序端**:按会员账号的 `staff_role` 判断,默认为顾客;Web 管理员将会员手机号授权为核销员/小程序管理员后,该账号「我的」页面出现「管理端」入口。
- **Vue3 网页管理端**:使用独立的 Web 管理账号(用户名+密码),不因某手机号被授权为小程序管理员而自动获得 Web 权限。

| 角色 | 判定 | 小程序权限 | 网页管理端权限 |
|---|---|---|---|
| 顾客 | 默认 | 注册登录、浏览活动、微信支付购卡、出示会员码、查看权益卡/订单、接收核销通知 | 无 |
| 核销员 | Web 管理员按手机号授权 | 含顾客全部能力 + 扫码核销(输入核销人 → 扫码 → 核销) | 无 |
| 小程序管理员 | Web 管理员按手机号授权 | 含核销员能力 + 现金发卡、数据速览 | 无(除非另有 Web 账号) |
| Web 管理员 | 独立 Web 账号 | 无(除非对应手机号另获小程序角色) | 卡商品/活动配置、会员管理、订单管理、核销记录、数据报表、角色授权、Web 账号管理 |

> 小程序管理端聚焦现场移动操作(核销、现金发卡、报表查看);重运营配置(卡商品/活动、授权、订单/会员管理)在 Vue3 网页管理端完成。两端共用同一后端与数据库,但身份体系和 API 权限边界相互独立。初始 Web 管理账号由数据库预置,初始小程序管理员需按会员手机号单独授权。

## 三、功能需求

### 3.1 用户端(顾客)

#### 3.1.1 登录与注册
- 进入小程序微信授权静默登录(openid)。
- 首次使用需获取手机号:点击「手机号一键登录」按钮(`button open-type="getPhoneNumber"`),前端将回调取得的动态凭证提交后端,由后端调用微信接口换取手机号;不得把会话密钥下发前端。
- **自动注册**:后端以手机号为唯一标识,不存在则自动创建会员账号;已存在则直接登录。
- 登录态持久化(token),失效重新授权。

#### 3.1.2 首页
自上而下:
1. **顶部栏**:门店名称「丽水湾洗浴中心」、Logo、营业状态(可选)。
2. **活动信息 Banner**:轮播图,展示门店活动(限时折扣、节假日活动),可配置跳转到卡商品。
3. **卡购买入口**:卡片列表/宫格,展示可购卡(大池卡、包间卡等),含缩略图、名称、价格、活动价标签。
4. **快捷功能**:会员码、我的订单等快捷入口。
5. **公告/温馨提示**:营业时间、注意事项。

#### 3.1.3 卡购买
点击某张卡 → **弹出购买页面**(半屏 popup / 新页面),展示:
- 卡名称、卡封面图
- 卡内容 / 权益明细(次数或时长、适用项目)
- **活动说明**(如有:限时折扣、赠送等)
- **有效期**(如"自购买之日起 90 天有效")
- 价格 / 活动价
- 适用规则(限本人使用、不可转赠等)
- 「立即购买」按钮(v1 不做购物车,见 3.1.4 说明)

> 顾客自助购卡走微信支付;v1 暂用模拟支付走通流程,预留微信支付接口,商户号就绪后切换。点「立即购买」→ 生成订单 → 模拟支付成功回调 → 生成权益卡。

#### 3.1.4 购物车
> v1 暂不做购物车,采用"单卡立即购买"。若后续需多卡合并结算再引入购物车。数据模型预留订单 items 为数组以兼容。

#### 3.1.5 我的(个人中心)
聚合入口,包含:
1. **个人信息**:头像、昵称、手机号(脱敏 138****1234)、注册时间;可改昵称/头像。
2. **会员码**:进入动态二维码页面,供门店扫码核销/发卡;码使用不含敏感明文的短期签名 token,约 60s 刷新并在成功操作后失效,降低截图盗用风险。
3. **权益卡**:列表展示已购卡(含微信支付自助购买与管理端现金发放两种来源):
   - 卡名称、剩余次数/时长、有效期、状态(未使用/使用中/已用完/已过期)
   - 点击进入卡详情:**卡内容** + **使用情况**(每次核销记录:时间、项目、扣减数量、核销人)
4. **我的订单**:全部/已完成/已关闭 列表;订单详情含卡商品、金额、支付方式(微信支付/现金)、支付时间、订单号。
5. **核销通知**:接收每次被核销的通知(订阅消息 + 站内消息列表)。
6. **管理端入口**(仅核销员/管理员可见):进入管理端。
7. **其他**:客服联系、关于门店、设置(退出登录)。

> 积分、会员等级:数据模型保留字段,v1 不显示、不计算。
> 微信订阅消息只能在用户主动触发并授权后发送,不保证送达;站内通知是必达记录,不得因订阅消息发送失败而回滚核销。

#### 3.1.6 核销通知
- 顾客被核销后,通过微信「订阅消息」推送通知(需顾客事先订阅授权)。
- 同时在「我的-核销通知」维护站内消息列表,避免订阅消息未授权时遗漏。

### 3.2 小程序管理端(核销员/管理员,移动现场操作)

#### 3.2.1 核销流程
1. 管理端首页(核销台)→ **输入核销人**(姓名/工号,本班次记住,可切换)。
2. 点击「扫码核销」→ 调用小程序扫码 → 识别顾客会员码。
3. 展示该会员名下所有可用权益卡及剩余权益。
4. 选择要核销的卡与权益项,输入扣减数量(次数/时长),确认核销。
5. 核销成功:实时扣减权益 → 写入核销记录(含核销人)→ 向顾客推送核销通知。
6. 核销失败提示(权益不足、卡过期、码失效等)。

核销约束:
- 核销员仅可核销;管理员可核销、现金发卡和查看数据速览。
- 会员码过期、签名错误、已被成功使用或所属会员被禁用时必须拒绝操作。
- 确认页必须展示会员脱敏信息、卡名、权益项、当前余额、本次扣减和扣减后余额。
- 核销提交须携带请求幂等号;只有数据库扣减与核销记录同时成功后才返回成功。
- “核销人”是当班现场人员姓名/工号,同时必须记录当前登录账号,两者共同用于审计。

#### 3.2.2 现金发卡流程(管理员)
顾客现金购卡时,由管理员在小程序管理端发卡(顾客须已有会员账号):
1. 管理端「现金发卡」→ **扫描顾客会员码**识别会员(或失败时提示顾客先登录小程序)。
2. 展示可售卡商品列表 → 选择卡商品。
3. 填写实收金额(现金金额,可与售价不同,记录实际收款)。
4. 确认发卡 → 生成订单(支付方式=现金,含操作管理员)→ 生成权益卡归属该会员。
5. 发卡成功后顾客端即可看到该权益卡;顾客端可见订单标注"现金购买"。
6. 向顾客推送"发卡成功"站内通知(可选订阅消息)。

> 现金发卡本质是"线下收款 + 线上发卡":订单金额以实收为准,不涉及线上支付通道。
> 确认页必须二次展示会员、卡商品、标准售价和实收金额;提交须携带请求幂等号。实收金额必须大于 0,与标准售价不一致时记录差额但不阻止发卡。

#### 3.2.3 核销记录
- 当日/历史核销记录列表:时间、会员(手机号脱敏)、卡、项目、扣减数量、核销人。
- 按核销人/会员/时间筛选。

#### 3.2.4 数据报表查看(管理员)
- 小程序端提供核心指标速览:销售额(微信/现金分项)、售卡数量、核销次数、新增会员。
- 详细图表与导出在 Vue3 网页管理端完成。

### 3.3 Vue3 网页管理端(电脑端重运营)

Web 管理员通过用户名+密码登录后台,完成重运营操作:

#### 3.3.1 卡商品管理
- 卡商品新增/编辑/上下架/逻辑删除;已产生订单的商品不可物理删除,字段见数据模型 card_product。
- 卡类型分类(大池/包间/其他)、权益明细(次数/时长/项目)、原价/售价/活动价、有效期天数、规则、封面图上传。

#### 3.3.2 活动管理
- 活动 Banner 配置:图片上传、标题、跳转目标(卡商品)、起止时间、排序、上下架。
- 配置即时生效,小程序首页实时读取最新数据。

#### 3.3.3 会员管理
- 会员列表:手机号(脱敏/完整按权限)、昵称、注册时间、累计消费、持有卡数。
- 会员详情:权益卡、订单、核销记录、备注;积分 v1 仅保留字段,不提供调整入口。

#### 3.3.4 订单管理
- 订单列表与详情:订单号、会员、卡商品、金额、支付方式(微信/现金)、状态、时间。
- 按支付方式/状态/时间筛选;支持导出 Excel。

#### 3.3.5 核销记录
- 全量核销记录查询:时间、会员、卡、项目、扣减数量、核销人。
- 按核销人/会员/时间筛选;支持导出。

#### 3.3.6 数据报表
- 核心指标:销售额(微信支付/现金分项)、售卡数量、核销次数、新增会员、各卡类型销售占比。
- 趋势图:按日/周/月的销售额与核销量;卡类型占比饼图。
- 时间区间筛选;导出 Excel。

#### 3.3.7 核销员与小程序管理员授权
- 输入手机号将会员标记为核销员/小程序管理员,或取消授权;目标手机号必须已注册会员。
- Web 端管理员账号管理(新增/禁用/改密);初始管理员账号在数据库预置。

## 四、卡与权益模型

### 4.1 卡类型示例
| 卡类型 | 权益形式 | 有效期示例 | 核销方式 |
|---|---|---|---|
| 大池次卡 | 大池入场 N 次 | 90 天 | 每次 1 次 |
| 大池月卡 | 大池不限次 | 30 天 | 有效期内不限次 |
| 包间时卡 | 包间使用 N 小时 | 90 天 | 按小时 |
| 包间次卡 | 包间使用 N 次 | 90 天 | 每次 1 次 |
| 综合卡 | 多项目组合权益 | 自定义 | 各权益独立核销 |

### 4.2 权益卡状态
`未使用` → `使用中` → `已用完`;任意状态可因过期转为 `已过期`。

- 首次成功核销后从“未使用”变为“使用中”。
- 所有有限权益均耗尽后变为“已用完”;含不限次权益的卡在有效期内不会变为“已用完”。
- 状态展示以“已过期”优先:到达 `valid_until` 后即使数据库定时任务尚未更新,查询与核销也必须按过期处理。

### 4.3 卡商品与权益卡关系
- **卡商品**:门店配置的可售模板。
- **权益卡**:顾客购买后生成的实例,绑定会员,独立有效期与剩余权益。

## 五、订单与支付流程

订单区分两种来源,共用同一订单模型,支付方式字段区分。

### 5.1 顾客微信支付自助购卡(v1 模拟支付)
1. 顾客选卡 → 立即购买 → 生成订单(待支付,pay_method=wechat)。
2. 模拟支付:前端调"模拟支付"接口 → 后端直接置「已支付」(预留微信支付回调位)。
3. 订单「已支付」→ 生成权益卡 → (预留积分发放钩子)。

订单超过 15 分钟未支付自动关闭;已关闭订单不可继续支付。模拟支付入口仅允许在非生产配置下启用,生产环境必须默认关闭。

### 5.2 管理端现金发卡
1. 管理员扫顾客会员码识别会员 → 选卡 → 填实收金额 → 确认发卡。
2. 后端生成订单(pay_method=cash,pay_status=已支付,含操作管理员与核销人)→ 生成权益卡归属该会员。
3. 无需走线上支付通道。

### 5.3 消费核销(两种购卡方式共用)
1. 顾客到店出示会员码 → 管理端扫码核销 → 扣减权益 → 写核销记录 → 推送核销通知。
2. 权益用完或过期 → 权益卡状态变更。

> 后期接入微信支付时,只需替换 5.1 的"模拟支付"为真实下单/调起/回调校验,订单与权益卡生成逻辑不变。

## 六、非功能需求
- **性能**:正常生产网络与服务负载下,首页接口、会员码生成、核销接口的服务端响应 P95 分别小于 2s、500ms、1s;核销指标不含异步订阅消息发送时间。
- **安全**:
  - 手机号后端解密,前端脱敏展示。
  - 会员码含签名 + 时间戳,短期刷新,防截图伪造。
  - 支付回调校验签名与订单状态幂等(为接入微信支付预留)。
  - 接口鉴权;管理端入口按角色(手机号)鉴权。
- **可用性**:弱网提示与重试。
- **一致性**:支付成功/现金发卡与权益卡生成必须在同一事务或可靠补偿机制内完成;核销扣减与核销记录必须在同一数据库事务内完成。
- **审计**:商品、活动、角色授权、现金发卡等管理操作记录操作账号、时间和变更内容,日志至少保留 180 天。
- **备份**:MySQL 每日备份,至少保留 7 天;上线前需完成一次恢复演练。
- **兼容性**:微信基础库适配主流机型,iOS/Android 双端。
- **合规**:遵循小程序运营规范与隐私要求,获取手机号前展示用途说明。

## 七、数据模型(概要)

> 积分/会员等级字段保留但 v1 不用。

- **member 会员**:id, openid, phone, nickname, avatar, staff_role(customer/verifier/admin), level(预留), points(预留), status, created_at
- **card_product 卡商品**:id, name, category, cover, benefits(json,每项含稳定的 benefit_id), price, sale_price, activity_price, activity_start_at, activity_end_at, valid_days, rules, status, deleted
- **order 订单**:id, order_no, member_id, payable_amount(应付), paid_amount(实收), pay_method(wechat/cash), pay_status, operator_member_id(现金发卡管理员,可空), paid_at, created_at
- **order_item 订单明细**:id, order_id, product_id, quantity(v1 固定 1), product_snapshot(json), unit_price
- **membership_card 权益卡**:id, member_id, product_id, order_item_id, benefits_remaining(json), valid_from, valid_until, status, version
- **verification 核销记录**:id, request_no, card_id, member_id, benefit_id, item_snapshot, quantity, operator_name(现场核销人), operator_member_id(登录账号), created_at
- **activity 活动**:id, title, image, target, start_at, end_at, sort, status
- **notification 站内通知**:id, member_id, type(核销通知), content(json), read, created_at
- **points_log 积分明细**(预留, v1 不写入):id, member_id, delta, source, ref_id, created_at
- **operation_log 操作日志**:id, operator_type, operator_id, action, target_type, target_id, detail(json), created_at
- **idempotency_record 幂等记录**:id, actor_type, actor_id, api_scope, request_no, status, response_snapshot, expire_at
- **consumed_member_code 已消费会员码**:nonce(唯一), member_id, action, created_at, expire_at

## 十二、v1 验收标准

| 编号 | 场景 | 验收结果 |
|---|---|---|
| AC-01 | 新用户完成微信登录并授权手机号 | 自动创建唯一会员,再次登录不重复创建 |
| AC-02 | 顾客购买一张上架卡并完成模拟支付 | 仅生成一笔已支付订单、一条订单明细和一张权益卡 |
| AC-03 | 同一支付请求重复提交 | 返回同一业务结果,不重复发卡 |
| AC-04 | 管理员现金发卡 | 订单实收金额、管理员账号与会员归属准确,顾客立即可见卡和通知 |
| AC-05 | 核销员扫描有效会员码并核销 | 余额准确扣减,核销记录同时落库,通知生成 |
| AC-06 | 同一核销请求重复提交或并发提交导致余额不足 | 不重复扣减、不出现负余额,返回明确结果 |
| AC-07 | 扫描过期、伪造、已成功使用的会员码 | 拒绝操作且不泄露会员敏感信息 |
| AC-08 | 商品修改或下架 | 历史订单与已购卡权益不变;下架商品不可新购 |
| AC-09 | 权益卡到达截止时刻 | 无论定时任务是否执行,均不可继续核销并展示为已过期 |
| AC-10 | 订阅消息发送失败 | 核销仍成功,站内通知可查询,失败有日志可追踪 |
| AC-11 | 角色权限校验 | 核销员不能现金发卡/看报表/Web 登录,顾客不能进入管理功能 |
| AC-12 | 报表与订单对账 | 销售额按实收金额统计,微信/现金分项合计与已支付订单一致 |
